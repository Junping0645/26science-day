# 26 과학의 날 — 병렬 A\* 미로 탐색기

과학의 날 부스에서 참가자들이 **협업으로 그린 미로**를, **MPI 병렬 A**로 풀어내는 프로젝트입니다.

미로를 만드는 과정도, 푸는 과정도 병렬입니다.
여러 사람이 각자 한 칸씩 동시에 그려 하나의 미로를 완성하고([웹 협업 도구](https://26science-day.pages.dev)), 완성된 미로는 여러 프로세스가 구역을 나눠 동시에 탐색합니다.

> 미로 생성 웹앱은 `main` 브랜치에 있습니다.

---

## 왜 병렬인가

A\*는 본래 순차 알고리즘입니다. 우선순위 큐에서 가장 유망한 노드를 하나 꺼내 확장하는 과정을 반복하므로, 여러 프로세스가 하나의 큐를 공유하면 **락 경합 때문에 프로세스를 늘려도 빨라지지 않습니다.**

그래서 큐를 공유하는 대신 **노드 자체를 나눠 소유**하는 방식(HDA\*, Hash Distributed A\*)을 택했습니다. 각 프로세스는 자기 소유 노드만 자기 큐에 넣고 독립적으로 탐색하며, 이웃이 남의 소유일 때만 메시지를 보냅니다. 락이 아예 필요 없습니다.

```
노드 (row, col) → 담당 rank 결정
                      ↓
          해당 rank의 로컬 큐에 삽입
                      ↓
          rank별 독립 탐색 (락 없음)
                      ↓
     이웃이 다른 rank 소유 → MPI Send
```

---

## 구현의 핵심

### 1. 열 기반 노드 분할

노드를 무작위 해시로 흩뿌리면 이웃끼리 다른 rank에 배정되어 **통신량이 폭증**합니다.
미로는 인접한 칸으로만 이동하므로, 공간적으로 가까운 노드를 같은 rank가 갖도록 **열(column) 단위로 분할**했습니다.

```python
def node_owner(node):
    # 같은 구역의 노드를 같은 rank에 묶어 통신 최소화
    return min(node[1] // _COL_WIDTH, SIZE - 1)
```

덕분에 대부분의 이웃 확장이 프로세스 내부에서 끝나고, 구역 경계를 넘을 때만 통신이 발생합니다.

### 2. 종료 판정 — 분산 탐색의 가장 어려운 부분

병렬 탐색에서 "언제 끝났는가"를 판단하는 것은 생각보다 까다롭습니다.
**모든 프로세스의 큐가 비어 있어도, 네트워크에 아직 도착하지 않은 메시지가 있다면 탐색은 끝난 것이 아니기 때문입니다.**

그래서 두 조건을 동시에 확인합니다.

```python
global_heap = comm.allreduce(local_heap, op=MPI.SUM)   # 전체 큐가 비었는가
global_sent = comm.allreduce(total_sent, op=MPI.SUM)   # 보낸 메시지 총합
global_recv = comm.allreduce(total_recv, op=MPI.SUM)   # 받은 메시지 총합

if global_heap == 0 and global_sent == global_recv:
    break   # 큐도 비었고, 비행 중인 메시지도 없음
```

송신 총합과 수신 총합이 같다는 것은 **전송 중인 메시지가 하나도 없다**는 뜻입니다. 이 조건을 함께 걸어야 경로를 놓치지 않고 안전하게 종료할 수 있습니다.

### 3. 목표 비용 공유로 탐색 가지치기

한 프로세스가 목표에 도달하면 그 비용을 다른 모든 프로세스에 방송합니다(`TAG_GOAL`).
각 프로세스는 이미 알려진 최선 비용보다 나쁜 경로를 만나면 즉시 버리므로, 불필요한 탐색이 줄어듭니다.

```python
if g >= best_cost:
    continue   # 이미 더 나은 경로가 있음
```

### 4. 경로 복원

탐색 중 각 프로세스는 자기가 확장한 노드의 부모 정보만 갖고 있습니다.
탐색이 끝나면 `comm.gather`로 rank 0에 모두 모아 하나로 병합한 뒤, 목표에서 시작점까지 역추적해 경로를 복원합니다.

## 구조

```
├── main.py          # 직렬 / 병렬 실행 및 성능 비교
├── maze_reader.py   # 미로 이미지 → 이진 격자 변환
├── astar_serial.py  # 직렬 A* (성능 비교 기준선)
├── astar_mpi.py     # HDA* 병렬 A* (mpi4py)
└── visualize.py     # 탐색 결과 경로 시각화
```

**직렬 구현을 함께 둔 이유**는 비교 대상이 있어야 병렬화의 효과를 수치로 말할 수 있기 때문입니다. 같은 미로를 두 방식으로 풀고 소요 시간과 속도 향상 배율을 함께 출력합니다.

---

## 미로 이미지 규칙

| 색상 | 의미 | 격자 값 |
|------|------|---------|
| 검정 | 벽 | 1 |
| 흰색 | 통로 | 0 |
| 초록 | 입구 | 0 (start) |
| 빨강 | 출구 | 0 (goal) |

## 실행 방법

### 설치

```bash
pip install mpi4py numpy pillow

# MPI 런타임
sudo apt install mpich          # Ubuntu / Debian
brew install mpich              # macOS
# Windows → Microsoft MPI 설치
```

### 미로 준비

1. https://26science-day.pages.dev 접속
2. 각 칸에 미로 그리기 (초록 = 입구, 빨강 = 출구)
3. **"구역 경계선 포함"을 해제**한 뒤 전체 병합 다운로드
4. 받은 PNG를 `maze.png`로 저장

> 경계선이 포함되면 격자 변환 시 벽으로 잘못 인식됩니다.

### 실행

```bash
python main.py maze.png              # 직렬 (기준선)
mpirun -n 4 python main.py maze.png  # 4 프로세스
mpirun -n 8 python main.py maze.png  # 8 프로세스
```

콘솔에 직렬·병렬 소요 시간과 속도 향상 배율이 출력되고, `result.png`에 탐색된 경로가 표시됩니다.

## 성능에 대해

- 미로가 클수록 병렬 효과가 커집니다. 작은 미로에서는 통신 비용이 계산 이득을 넘어서기도 합니다.
- 프로세스 수는 CPU 물리 코어 수에 맞추는 것이 가장 효율적입니다.
- 열 분할 방식이므로, **세로로 긴 미로**보다 **가로로 넓은 미로**에서 부하가 고르게 나뉩니다.

---

## 개선 아이디어

- **동적 부하 분산** — 현재는 열을 균등 분할하므로, 벽이 많은 구역을 맡은 프로세스가 일찍 놀게 됩니다.
- **비동기 통신** — `comm.send`를 `Isend`로 바꾸면 전송 대기 시간을 줄일 수 있습니다.
- **2차원 분할** — 열이 아닌 격자 블록 단위로 나누면 정사각형에 가까운 미로에서 통신량이 줄어듭니다.
